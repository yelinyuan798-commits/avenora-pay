# 平台订阅收费与额度

本模块给使用此平台的商户提供月订阅，不接触 DujiaoPay 官方账户或余额。平台运营者使用自己的收款项目收取订阅费用。商户资金仍直接进入各商户自己的钱包。

## 配置收费

在 `CHAIN_CONFIG_PATH` 指向的服务端私有配置中添加：

```json
{
  "billing": {
    "enabled": false,
    "adminMerchantId": "在本平台注册的运营者 merchant ID",
    "ownerProjectId": "归属于该运营者的订阅收款 project ID",
    "graceDays": 3
  }
}
```

先注册运营者账户、创建项目、配置真实收款地址及节点和起扫高度，再将真实 ID 填入配置并设置 `enabled: true`，重启服务。平台管理员仅由该配置中的商户 ID 决定，不以首个注册者、邮箱或请求中的角色字段决定。配置文件应保持私有。

`enabled` 未开启、管理员账户不存在、项目不归管理员，或没有可用地址和代币节点配置时，真实订阅建单返回 `BILLING_DISABLED`，界面显示未开启。静态配置通过不代表已完成真实链上收款验收；仍应通过平台正常收款验证节点和对账。

演示商户可以生成合成订阅账单，模拟付款只激活该演示商户的权益。演示商户不能成为平台管理员，也不能激活真实商户订阅。演示资源不受真实套餐额度限制，以便完整检查流程。

## 月订阅流程

1. 商户提交套餐 ID 和随机幂等请求编号。
2. 服务端锁定套餐价格，并在平台运营者的项目里创建真实支付订单；付款地址、币种和精确金额由既有支付引擎分配。
3. 商户进入普通收银台付款。浏览器回跳、客户端声明已付款或提交 `status: paid` 都不会激活订阅。
4. 扫描器确认付款后，`Store.settle` 在同一数据库事务中执行 `afterPaid`。模块再次核对账单、付款订单归属、金额、币种与演示/真实环境，随后只激活一次。
5. 同档续费在当前有效期结束后再增加一个自然月；每个商户最多有一张待支付订阅账单。到期后默认宽限3天，宽限期间保留原档权益；宽限内同档续费从付款时刻重新开始一个自然月。不同档位需当前套餐及宽限期结束后再购买，不隐式折算余额。

自然月采用 UTC 日历月，到下个月没有同一天时取月末。月末续费不固定等于30天。幂等重放及扫描重试不会重复延长有效期。可以取消仍未发现付款的待支付账单，已确认或正在确认的账单不能直接取消。

## 后端额度

默认新商户使用 Free。Starter、Pro、Business 初始月费为 10、20、50 USD，运营者可以修改名称、价格、启用状态和额度。套餐修改影响之后新开的账单价格；已开账单的价格不变。

资源额度在后端创建操作中执行，包括项目、收款地址、每项目地址、有效 API Key、Webhook endpoint、收款链接、商品数。停用地址/链接仍占已创建资源数量；撤销的 API Key 不再占有效密钥额度。项目、地址和链接配额不是只在页面上禁用按钮。

订单额度有两层：正在等待或处理的订单数，以及当月已支付订单数。创建订单时还为待支付、确认中和缺货待处理订单预留月度名额，避免多个并发付款窗口越过上限。签名 API 请求按商户以一分钟窗口持久计数，超额返回 HTTP 429。

GMV 使用**每次收款报价锁定的美元价值**，包含商户手续费、换算向上舍入及唯一付款尾差。BTC、ETH、BNB、SOL、TRX 的币数量不能当作美元数量；每份报价保存当时的币/USD价格、法币/USD换算、来源、时间和18位精度 `usd_atomic`。原生币和稳定币的新市场报价均采用服务端缓存，付款后不按最新行情重算计费金额。显式选择 `pricing.stablePolicy: "parity"` 的离线平价政策只适用于已知USDT/USDC及USDT0，不适用于原生币，快照会标注该政策。详见[价格与锁价](pricing.md)。

选定或改选支付方式时，已支付GMV加所有未结束订单的锁定USD价值加当前报价不得超过硬上限。重新选择会排除本订单旧报价，失败会回滚金额预留；历史尾差仍永久占位，不会分配给新单。所有额度计算使用18位 `BigInt`，不使用浮点数。历史订单若缺少价格快照，只有明确识别的旧稳定币订单可按保守平价回填并标记 `legacy_stable_parity`。未知或非稳定币历史订单标记计价不完整（`valuation_incomplete`），阻止继续创建/报价，不能隐式按1币=1美元或0美元计算。

每月已支付订单和 GMV 有独立软提醒阈值、硬上限。软阈值用于展示，硬上限会拒绝新的订单或报价。月份以 UTC 为准。平台自身的订阅收费通过可信 `billing_invoices` 关联识别，不计入普通商户 GMV；客户在 metadata 中伪造 `kind: platform_subscription` 无法绕过统计。

订阅到期后进入 `grace` 宽限状态，`grace_until` 给出截止时间，期间仍按原套餐执行额度。服务端 `billing.graceDays` 默认为3，可设置为0–30的整数；0表示不宽限。宽限结束后读取权益和执行额度自动按 Free 限额处理，已存在的数据保留。对到期或降档前已经发出的有效付款指令仍须正常核对入账，不会为了额度而丢弃已收款；在旧额度下产生的未结束订单可能使到期后的占用量高于新额度，此时禁止继续创建，直至占用回落或续订。迁移前历史订单没有精确支付时间，模块以原订单创建时间回填并标记 `legacy_creation_time`；之后的新付款使用真实处理时间计月。

Starter 初始限额：项目3、商户地址总数30且每项目10、有效 API Key 3、Webhook 2、收款链接5、商品50、待处理订单50、API每分钟120次、月付费订单软1000/硬1500、月GMV软5000/硬6000计费USD。其他档位以后台表格的当前配置为准。

## 管理员操作

- `GET /api/platform/plans`、`PATCH /api/platform/plans`：查看/修改套餐。
- `GET /api/platform/merchants`、`GET /api/platform/invoices`：平台商户、权益、使用量和账单。
- `POST /api/platform/merchants/:id/grant`：带理由的人工开通或调整，明确记录为 `admin_grant`，不创建虚假的已支付账单；商户存在待付账单时拒绝，以避免后续到账覆盖人工调整。
- `GET /api/platform/grants`：审计记录。普通商户和演示商户无法访问。

商户通过 `GET /api/subscription` 查看权益和额度，通过 `GET /api/billing` 查看自己的账单。公开 `GET /plans` 提供当前价目。`POST /api/billing/invoices/:id/simulate` 只供隔离演示；真实商户和其他人的账单都会被拒绝。

当前未接入自动扣款、信用卡、税务发票或跨档余额折算。订阅属于用户主动付款续期；账单为平台内部交易记录，不宣称税务发票。后台人工赠送权益不代表收到了付款。

## 验证

`tests/billing.test.mjs` 检查收费配置未就绪时拒绝、账单幂等、付款后一次激活、续费、隔离与伪造付款拒绝、管理员权限、审计赠送、到期降级、资源/订单/API额度、精确GMV预留，以及演示订阅隔离。真实运营者钱包的订阅到账尚需在部署环境完成验收，测试不会替运营者转账或保管私钥。
