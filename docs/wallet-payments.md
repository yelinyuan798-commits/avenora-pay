# 同一个地址、同一个价格的自动收款

项目选择“钱包支付自动认单”后，新订单不再添加识别尾数。基础金额为1.0 USDT的订单均支付1.0 USDT，可以共用商户原有收款地址。每个付款报价另有随机订单标识，服务端从实际成功交易中提取并核验它，随后自动确认和发货。

## 买家操作

1. 在收银台点击“钱包支付”，连接支持EIP-1193的浏览器钱包，例如MetaMask或兼容的OKX钱包。
2. 核对网络、USDT金额、收款地址和网络费，在钱包确认转账。BSC网络费由付款钱包另付，需保留足够BNB。
3. 保持订单页等待，服务端识别到账、等待链上确认并交付商品。钱包返回交易hash只表示已提交，不表示支付成功。

必须从本订单收银台发起。交易所提币、手动复制地址转账、二维码普通转账不会自动携带订单标识，不能用来支付此类订单。收银台因此不提供普通转账二维码或主要复制转账入口。浏览器未装钱包时提示使用支持的钱包环境；本实现没有额外集成WalletConnect或手机深链。

钱包未返回确定结果时应先查看钱包记录，不能盲目重发。页面保存当前订单的提交状态以减少刷新重复付款；换浏览器或换设备不共享这份本地状态。最终只有服务端链上核验可以改变付款状态。

## 商户与部署配置

商户保留公开收款地址，在“收款地址”页为项目开启“钱包支付自动认单”。设置只影响新订单；既有订单、报价、付款来源、库存与通知记录保持原样。默认仍是`amount`模式。

真实方式需要运营方先核对代币的兼容性，再在私有链配置中为该代币显式设置`paymentReference:true`。例如BSC USDT配置条目：

```json
{"id":"bsc-usdt","contract":"0x55d398326f99059ff775485246999027b3197955","decimals":18,"paymentReference":true}
```

这只是代币条目，还需正确的BSC网络、节点、`chainId:56`、扫描起点与商户地址配置。BSC的该资产为Binance-Peg USDT；不能仅凭代币名称替换合约。当前实际只读验证只覆盖这一合约，不能据此宣称所有ERC-20、智能合约钱包或交易所兼容。

2026-11-04在BSC区块131559926对该合约进行带标识转账的只读`eth_call`，返回成功；`eth_estimateGas`返回30920。模拟未签名、未广播、未转出资产。此记录证明该合约当时可接受附加数据，**不等于已经完成新付款方式的真实钱包端到端验收**。

## 标识及核验

交易调用代币的`transfer(address,uint256)`，后附两个32字节字段：ASCII `AVENORA_PAY_REF_V1`右侧补零，以及随机非零32字节订单引用。整体132字节，标准收款地址和原子金额参数不变。没有新支付合约，没有代币授权，没有平台签名或托管私钥。

扫描器读取规范区块、成功回执、同一Transfer日志和原交易输入，核对代币合约、发起人、收款人、零原生币value及精确到账数量。数据缺失时停止该批扫描；带标识但结构或身份冲突时不回退为金额匹配。服务端以永久唯一引用关联当前报价，并独立核对商户、项目、链、币、地址、金额、付款窗口和确认数。

无标识款项不会进入reference订单候选。未知、旧报价或错误标识也不会回退归到其他金额订单。已绑定的交易不可更改订单；每笔付款事件及库存交付具有幂等约束。旧amount订单仍按自己的原规则识别普通转账。

新报价精确等于包含商户手续费的基础数量，不免除本金。不同币种报价可各有自己的引用；改选不延长付款窗口，切回原方式恢复原报价及引用。关闭或修改项目模式不改变已创建订单的模式。

## 自动恢复

私有配置可以开启：

```json
{"payments":{"automaticRecovery":true,"recoveryBatchSize":5}}
```

每轮所有链合计最多复查5个旧区块，允许配置1–50；任务持久排队，失败从30秒指数退避，最高1小时。旧块失败不阻断正常新块扫描。补库存和延迟确认都须重新验链，不能仅根据缓存转账直接发货。库存为空时页面显示等待补货，补货后自动交付一次。

reference订单的转账若在原付款窗口内入块，可以自动恢复过期后的迟扫状态；取消、窗口外、错误金额或错误标识不会凭猜测发货。普通金额模式继续保持原过期规则。深度重组、节点长期不可用及未支持的转账仍需运营处理，系统不能自动制造库存或自动退款。

开启自动恢复后，失败的Webhook在常规重试后继续每小时重试，保留原事件ID和消息体；接收商城仍必须按事件ID幂等履约。

## 验收

自动测试包含同址同价反序付款、无/错/旧标识、身份冲突、缺回执、重组、原窗口迟扫、SQLite旧数据迁移、补库存、重启恢复和重复通知。公开演示使用合成地址，按钮为“模拟钱包支付（不转账）”，不生成可广播的真实付款数据。

正式验收还需用户在实际钱包确认小额付款，核对交易hash、商户实收、订单确认及只发一份商品；本程序与自动测试不会替用户签名或转币。
